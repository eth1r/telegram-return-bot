# Финальное исправление Workflow

## Исправленные проблемы

### Проблема 1: Преждевременная отправка заявки после отказа на purchase_date
**Было:** После отказа пользователя на вопрос о дате покупки бот сразу отправлял заявку, не спрашивая про способ возврата.

**Исправлено:** Добавлено условие `not should_ask_optional` в проверку `ready_to_send`. Теперь бот НЕ отправляет заявку, если нужно задать вопрос о необязательном поле.

### Проблема 2: Перезапись уже заполненных обязательных полей
**Было:** Метод `merge()` перезаписывал все непустые поля, включая уже заполненные обязательные (например, имя "Егор" заменялось на "Федор" из последующего сообщения).

**Исправлено:** Добавлен параметр `protect_required=True` в метод `merge()`, который защищает уже заполненные обязательные поля от перезаписи.

## Изменённые файлы

### 1. `core/schemas.py` - метод `merge()`

**Было:**
```python
def merge(self, other: "SupportTicket") -> None:
    for field_name, value in other.model_dump().items():
        if value not in (None, ""):
            setattr(self, field_name, value)  # ❌ Перезаписывает всё
```

**Стало:**
```python
def merge(self, other: "SupportTicket", protect_required: bool = False) -> None:
    """
    Объединяет данные из другого тикета.
    
    Args:
        other: Тикет с новыми данными
        protect_required: Если True, не перезаписывает уже заполненные обязательные поля
    """
    required_fields = {"name", "contact", "order_number", "product_name", "return_reason", "item_condition"}
    
    for field_name, value in other.model_dump().items():
        if value not in (None, ""):
            # Если защита включена и поле обязательное и уже заполнено - не перезаписываем
            if protect_required and field_name in required_fields:
                current_value = getattr(self, field_name)
                if current_value not in (None, ""):
                    continue  # ✅ Пропускаем перезапись
            
            setattr(self, field_name, value)
```

### 2. `services/workflow.py` - логика обработки

**Ключевые изменения:**

1. **Определение текущего этапа ДО обновления данных:**
```python
# Определяем, на каком этапе мы находимся
required_complete = session.ticket.is_complete()
waiting_for_purchase_date = (
    required_complete 
    and not session.ticket.purchase_date 
    and not session.purchase_date_asked
)
waiting_for_refund_method = (
    required_complete 
    and (session.ticket.purchase_date or session.purchase_date_asked)
    and not session.ticket.refund_method 
    and not session.refund_method_asked
)
```

2. **Правильная обработка отказа:**
```python
if user_declined:
    # Если пользователь отказался, помечаем соответствующий флаг
    if waiting_for_purchase_date:
        session.purchase_date_asked = True
        logger.info("User declined to provide purchase_date")
    elif waiting_for_refund_method:
        session.refund_method_asked = True
        logger.info("User declined to provide refund_method")
    else:
        # Отказ на этапе сбора обязательных полей - обновляем как обычно
        session.ticket.merge(turn.extracted_ticket, protect_required=True)
else:
    # Пользователь дал нормальный ответ
    # Защищаем обязательные поля от перезаписи
    session.ticket.merge(turn.extracted_ticket, protect_required=True)
```

3. **Исправленное условие отправки:**
```python
ready_to_send = (
    required_complete 
    and (session.ticket.purchase_date or session.purchase_date_asked)
    and (session.ticket.refund_method or session.refund_method_asked)
    and turn.ready_to_submit
    and not should_ask_optional  # ✅ КРИТИЧНО: не отправляем, если нужно задать вопрос
)
```

## Точное условие отправки заявки

Заявка отправляется ТОЛЬКО если выполнены ВСЕ условия:

1. ✅ `required_complete` - все обязательные поля заполнены (name, contact, order_number, product_name, return_reason, item_condition)
2. ✅ `(session.ticket.purchase_date or session.purchase_date_asked)` - дата покупки либо указана, либо уже спрашивали
3. ✅ `(session.ticket.refund_method or session.refund_method_asked)` - способ возврата либо указан, либо уже спрашивали
4. ✅ `turn.ready_to_submit` - ассистент подтвердил готовность
5. ✅ `not should_ask_optional` - НЕТ необходимости задавать вопрос о необязательном поле прямо сейчас

**Последнее условие критично!** Оно предотвращает отправку заявки в момент, когда бот должен задать вопрос о `refund_method`.

## Защита уже заполненных полей

### Защищённые поля (не перезаписываются):
- `name` - имя клиента
- `contact` - контакт
- `order_number` - номер заказа
- `product_name` - название товара
- `return_reason` - причина возврата
- `item_condition` - состояние товара

### Незащищённые поля (могут обновляться):
- `purchase_date` - дата покупки (необязательное)
- `refund_method` - способ возврата (необязательное)

### Механизм защиты:
```python
session.ticket.merge(turn.extracted_ticket, protect_required=True)
```

При `protect_required=True`:
- Если обязательное поле уже заполнено → пропускается
- Если обязательное поле пустое → заполняется
- Необязательные поля обновляются всегда

## Логирование для отладки

Добавлено логирование ключевых событий:
- `"Asking for purchase_date for user_id=%s"` - задан вопрос о дате
- `"User declined to provide purchase_date for user_id=%s"` - отказ от даты
- `"Asking for refund_method for user_id=%s"` - задан вопрос о способе возврата
- `"User declined to provide refund_method for user_id=%s"` - отказ от способа возврата
- `"Ticket submitted for user_id=%s"` - заявка отправлена

## Итоговая логика

1. **Сбор обязательных полей** → защита от перезаписи включена
2. **Вопрос о purchase_date** → флаг устанавливается, но заявка НЕ отправляется
3. **Обработка ответа на purchase_date** → переход к следующему шагу
4. **Вопрос о refund_method** → флаг устанавливается, но заявка НЕ отправляется
5. **Обработка ответа на refund_method** → теперь можно отправлять заявку
6. **Отправка заявки** → только если все условия выполнены

Грубые ответы, отказы, эмоциональные реакции без данных → распознаются как отказ, но не ломают сценарий.
